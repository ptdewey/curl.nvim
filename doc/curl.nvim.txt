USAGE                                                      *curl.nvim-usage*

Requires Neovim 0.11+, Linux/macOS, and Bash (or a configured compatible shell).
Notebook requests need curl when they call it. jq is not required.

Keep notebooks as regular project files, usually .sh. The plugin installs no
source filetype or keymaps. Map the Lua API directly; setup() is optional:
>lua
    vim.keymap.set("n", "<leader>rr", function()
      require("curl").run()
    end, { desc = "Run request block" })
    vim.keymap.set("n", "<leader>rc", function()
      require("curl").cancel()
    end, { desc = "Cancel request" })
<
Calling require("curl").setup() also registers :CurlRun and :CurlCancel.
:checkhealth curl checks the configured shell and curl availability.

NOTEBOOK FORMAT                                            *curl.nvim-notebooks*

Everything before the first ### marker is shared shell setup. A marker is ###
at column one followed by whitespace and a title, or end of line. The marker and
all following lines until the next marker form one request. Blank lines belong
to their containing block. Matching marker lines are reserved even inside quoted
bodies or heredocs. Each section must be a complete shell fragment.
>sh
    BASE_URL=http://localhost:8000

    ### Read application
    APPLICATION_ID=48047
    curl --silent --show-error "$BASE_URL/applications/$APPLICATION_ID"

    ### Create application
    curl --silent --show-error "$BASE_URL/applications" \
      --header 'Content-Type: application/json' \
      --data '{"name":"Example"}'
<
A run snapshots unsaved source and executes setup plus only the selected block
in a fresh asynchronous shell. It runs all code in that block, not just curl.
Assignments in other blocks or previous runs do not carry over. Neither filetype
nor extension affects execution. No process starts for setup-only cursor
positions, missing markers, or empty/comment-only blocks.

A final nonzero setup status or explicit exit prevents request execution. Check
intermediate failures yourself or choose an appropriate shell option; the plugin
does not enable errexit. Normal shell quotes, continuations, variables and heredocs
are preserved. Single-quoted bodies are literal. No curl flags are injected.

Relative paths resolve from the notebook's directory, or Neovim's current directory
for unnamed buffers. Opening, editing and saving neither run code nor autosave.
Running the entire notebook directly in a terminal may execute every request.

LUA API                                                    *curl.nvim-api*

require("curl").run()                                       *curl.nvim-run*
    Execute the current buffer's selected block with default or configured options.
    Does not require setup().

require("curl").cancel(bufnr?)                              *curl.nvim-cancel*
    Cancel the active request for the given source buffer, defaulting to current.
    Stops the shell and its children; server-side effects cannot be undone.

require("curl").setup(opts?)                               *curl.nvim-setup*
    Reset configuration to defaults, apply opts, and register commands:
    :CurlRun       Run the current buffer's selected block.
    :CurlCancel    Cancel the current source buffer's execution.

CONFIGURATION                                              *curl.nvim-configuration*

Complete defaults:
>lua
    require("curl").setup({
      shell = { "bash", "--noprofile", "--norc" },
      output_split_direction = "vertical",
    })
<
Use "horizontal" for a horizontal response split. Shell is an argv list; it
replaces the default list rather than merging. Do not include -c or a script
argument: the runner appends its private script path. Missing shells are errors,
not a reason to fall back to another dialect. Unknown options are rejected.

RESULTS                                                    *curl.nvim-results*

With mini.notify configured before running a request, a notification shows a
spinner and elapsed seconds, then disappears when the request ends. Otherwise,
the plugin sends one ordinary vim.notify message when the request starts.
No percentage is shown because arbitrary shell requests have no known total.

All scripts share one scratch response buffer and reuse its split. Each finished
request replaces the displayed result with its title, working directory, process
exit status, elapsed time, stdout, and stderr. Failure preserves both streams.
JSON gets pretty-printing and JSON highlighting, with metadata and stderr
highlighted separately. Text, invalid JSON and empty responses remain visible.

Use curl --include for headers. HTTP error responses may have process status zero
unless the command uses --fail or a related flag. Shell source selects curl
binaries and flags; the plugin does not rewrite commands.

Only one run is allowed per source buffer. Cancel or wait before running again.
Wiping a source cancels its execution but leaves the shared response buffer
intact. No response history is persisted.

SAFETY                                                     *curl.nvim-safety*

Only run trusted notebooks. Setup, substitutions and sourced files are executable
shell code, not passive request data. No .env file is sourced automatically.
The child inherits Neovim's environment but assignments do not mutate the editor
or persist between invocations. This is not a filesystem or network sandbox.

Default Bash startup files, including BASH_ENV, are disabled. Private temporary
scripts are removed after success, failure or cancellation. Saved notebook secrets
are ordinary plaintext. No expanded commands or response bodies are persisted.

MIGRATION                                                  *curl.nvim-migration*

Legacy execution, collections, scratch-file storage, source .curl filetype
registration, and default mappings are removed. CurlOpen, CurlCollection, CurlClose
and their Lua APIs no longer exist. Existing stdpath("data")/curl_cache files are
left untouched; open, convert and save them yourself wherever you prefer.

Use run() instead of execute_curl()/execute_notebook(), and cancel() instead of
cancel_notebook(). Rename notebook_shell to shell. Remove notebook_mode, mappings,
open_with, default_flags, curl_binary and show_request_duration_limit settings.

Replace ---name=value directives with shell assignments, put shared setup above
the first ### marker, and use normal quoting/continuations. Valid notebook content
still runs from .curl files, without special filetype handling.
